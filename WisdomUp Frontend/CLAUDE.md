- SEARCH ENGINE (`runSearch()` + `searchIndex()` in common.js, used by `mountSearch()`; all in the browser): forgiving text (case, dashes and spaces don't matter for model codes — "ts11", "TS 11", "cdb-18"; "type c"/"usb c" → usb-c; "power bank"/"hands free" joined; plurals fall back to the singular); shoppers' words → catalogue words (`SYN`: airpods/tws → earbuds, adapter/plug → charger, lav/mic → microphone, wire/cord → cable, mouse ↔ mice, trimmer/beard → clipper …); SPELLING: a word found nowhere in the catalogue is matched to the closest catalogue word (Levenshtein 1 edit for 4–6 letters, 2 from 7; ties go to the commoner word) and the "why" line says "Showing results for “…”"; PRICE INTENT: "under 3000", "below 2k", "upto Rs.5,000" filter by price — if only weak matches fit the budget it shows "Nothing under Rs.x — lowest prices first" with the real matches; SCORING per word: model code 14 exact / 10 start › CATEGORY 7 › name 6 (word start) / 4 › department 2 › specs/text 1, a synonym or correction 80%, each word weighted by RARITY (idf — "mouse" outweighs "wireless"); every word must match, else "No exact match — closest products" (most words); ties: the visitor's interests (only with consent) › best seller › new. While typing, CATEGORY CHIPS show the types the results fall in with counts (linking to the category, with the budget band when a price was typed); help pages still match ("warranty" → Warranty Policy, label "No products — see the page above"). STOP words (for, with, price, pakistan, buy, best, new, cheap …) are ignored.
- PERSONALISED SUGGESTIONS (common.js "PERSONALISED SUGGESTIONS" block; `WU.taste`): a very light on-device interest model in localStorage `wu-taste` — ONLY with the new consent category "Personalised suggestions" (cookie popup v2: `wu-consent` = `{ v: 2, marketing, personal, at }`; a v1 choice is asked again; "Accept all" = on, "Essential only" = off, a switch in Manage settings; switching it off DELETES the data). Never sent anywhere. Signals → points: product opened +1 (type +.5) + VISIBLE time on it ÷ 30 s (max +6 a visit; `watchTime()` only counts while the tab is visible); category page +1 + time ÷ 60 s (max +2); a search (counted once the visitor pauses 1.5 s, presses Enter, opens a result or closes search): the term is kept (8 newest) and the top result types get +.6/.45/.3/.2; search result opened +2 (type +1); add to cart +4 (type +2); wishlist +3 (type +1.5). Scores HALVE every 10 days. Preferred price = weighted mean of log(price). `suggest()` = 3 × type interest + .8 × department + 1.2 × product + .8 × price fit + best/new nudges − already in cart; max 2 per type. EMPTY SEARCH shows "Recent searches" (chips, Clear) and "Picked for you" with the reason ("Based on what you’ve been looking at — ‹top two types›") and "Clear history"; with no consent or no history it stays "Popular right now". The cookie popup text and the category description must stay true to these signals.
