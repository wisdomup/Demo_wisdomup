- SEARCH ENGINE v2 (2026-10-08, "enhance the search engine … go beyond the text errors and still serve the users with best matches … do the research"; `understand()` + `runSearch()` + `searchIndex()` in common.js, used by `mountSearch()`; all in the browser, ~0.6 ms a query, no model download). RESEARCH BASIS: e-commerce query understanding = category + attribute + number extraction; null-query recovery by dropping the least important term (eBay query-rewrite work: simple rules recover most null queries); Roman Urdu spellings vary per person, so read it by sound; per-user recent behaviour beats population stats for vague queries (eBay IntentTune); an in-browser embedding model (all-MiniLM-L6-v2 ≈ 23 MB quantised + runtime, ~0.4–0.5 s/query on WASM) was REJECTED as too heavy for this shop on Pakistani mobile data — revisit only with a server and real query logs. PIPELINE: (1) NORMALISE — `PHRASES` join "type c" → usb-c, "power bank", "memory card", "card reader", "wireless charger", "extension board" → powerstrip, "noise cancelling" → anc …; `FILL` drops English + Roman Urdu filler (for, my, something, phone, ka, ke liye, wala, chahiye …); Roman Urdu is matched by sound (`phon()`: doubled letters, ee/oo/aa, h after consonants, final vowels) so gaari/gari, awaz/awaaz, daarhi/darhi meet one entry. (2) UNDERSTAND — price limits ("under 3000", "2k tak", "2000 se kam") and ranges ("2000-5000", "2000 se 5000 tak"), cheap/sasta = lowest first, premium/mehnga = highest; numbers with units (mAh — also a bare 20000 next to "power bank" —, W, GB, m); devices (iPhone 15+ → USB-C, older iPhone → Lightning, plain "iphone" → Lightning .6, Samsung/Infinix/Tecno/Redmi … → USB-C); attributes (`ATTR_WORDS`: anc, water, fast, magnetic, wireless — a wired product is a poor fit —, wired, lights, battery/long, small, loud/power = more watts; "zyada/more" goes to loud or battery); `LEXICON`: 'p' PRODUCT words (earbuds, charger, cable, mic, machine …) with weighted categories and 'c' CONTEXT words (car, music/gaane, gym, gift/tohfa, tv, laptop, desk/mez, beard/daarhi, hair/baal, kids/bachon, old/purana …) whose weights ADD UP; `INTENTS` = combinations that mean one thing (car + music → Car Bluetooth & FM; car + charger → car chargers; old/make/"X to bluetooth" → receivers; gym + headphones → sports earbuds/neckbands; laptop + tv → HDMI; laptop + charger → high wattage); "X with Y" and "Y wala X": Y only DESCRIBES X ("earphones with mic", "mic wale earphones"); codes typed with a space are joined ("cdb 18"). (3) MATCH — product words are REQUIRED but met by their category (weight ≥ .3) or a name/category text match; context words only steer; other words must appear in the text; an unknown word is corrected by Damerau edit distance (1 edit for 4–6 letters, 2 from 7; a swapped pair = 1), then letter trigrams (≥ .45), then a shared stem — or set aside. (4) RANK — text × word rarity (idf) + 9 × category fit + attributes (+4 each; connectors +6, wrong connector on a cable/charger/handsfree −3; mAh/W/GB/m met +4–5, missed −2/−3) + price wish + 1.5 × the shopper's interests (3 × for a vague one-word query like "charger") + up to +8 for the product THIS device opened after the same search (`tasteQueryClick`, consent only, wu-taste `q`) + best/new. (5) RECOVER — nothing meets every required word → drop the least important (text words before product words/codes) → "No exact match for “x” — closest products"; a needs-only query keeps the categories within 50% of the best fit; a budget nothing meets → "Nothing under Rs.x — lowest prices first".
