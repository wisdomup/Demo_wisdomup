# Nav rule: one fixed bar at a time (decided 2026-10-05)
- A page may mark ONE sticky bar with `data-priority-bar` (today: All Products filter bar `#mbar`, product page section tabs `#pdtabs`). It outranks the site nav: while the bar is stuck at the top the nav stays hidden even on scroll-up; the nav returns only once the bar is back in its normal place with room for the nav above it (logic in `placeNav()` in `common.js`). The product tabs' stuck `top` is its own (16px / 10px phone); the All Products filter bar is not sticky at all — it is the priority bar by position, and its floating twin takes the nav's spot — never offset for the nav.
- Nav size (Ronin-style, measured on ronin.pk 2026-10-05): desktop/tablet pill 56px tall (40px row + 8px padding, 0 22px 0 28px), 22px inside the hero; category buttons 40px tall with 24px icons and 4px gaps; Shop All 40px pill, 14px text; search/account/wishlist/cart 34px buttons with 22px icons; logo 30px tall. Phone nav stays 43px. Content under a non-hero nav starts at `.nav-spacer` 96px.
- Nav skin (decided 2026-10-06): smoked frosted glass — dark tint `rgba(22,18,17,.64)` (lighter `rgba(86,78,74,.30)` over dark banners via `.on-dark`), 30px blur, hair-thin 0.5px edge `rgba(226,232,255,.12)` (`::before`, taken from ClickUp Brain² on 2026-10-06) with a soft cool inset glow, fine grain (`::after`), soft sheen. Inner pills (Shop All, current category) use the same 0.5px hairline. Icons and logo are ALWAYS white; never bring back dark icons on light pages. Styles in `site/css/home.css` (`.site-nav`).
- Nav edge light (requested 2026-10-06, approved exception to the subtle-motion rule): one rainbow arc glides clockwise round the nav's 1px edge — speed, length and colours copied from the "Memory Updated" card on clickup.com/lp/brain: one lap per 4s on average, lit arc ≈ 40% of the edge (short orange head `#ed5f00` → magenta `#ff02f0` → blue `#0091ff` → fade-out tail). `.wu-edge` (1px ring mask) is painted each frame by `runEdges()` in common.js, which places the colours by distance along the pill outline (a plain conic gradient would race across a long bar). SPEED is elastic but forward-only (2026-10-06: the first spring version overshot and bounced — the user found it too aggressive; never let the light run backwards or bounce): a steady drift carries 35% of the pace and a soft pull every 2s the rest, smoothed by a low-pass plus a critically damped spring (`EDGE_FREQ` 4 rad/s, `EDGE_SOFT` 5/s, `EDGE_SHARE` .65), so the speed swells to ~1.9× the average and relaxes to ~0.4×. Speed only — never the colours/length/line. Same motion on the nav and the floating filter capsule. Pauses while the nav is hidden; off for prefers-reduced-motion.
- All Products header layout (requested 2026-10-06): one centred stack — small muted breadcrumb → big title → one-line blurb with "read more" → the centred filter capsule — then the grid toolbar: item count on the LEFT, Sort (and the phone 1/2-per-row toggle) on the RIGHT; the sort menu opens from the right edge. No divider lines in this header.
- Filter capsule (requested 2026-10-06): the All Products filter bar is a capsule of chips, the same component as the product page's section tabs (`.pdtabs`), with no dropdown chevrons. IN THE PAGE (`.mbar`): the tabs' exact look and sizes — light grey glass capsule 48px tall (8px padding, 4px gaps), 32px chips, 12px/600 text, 13px side padding, a set filter = white pill. It is NOT sticky — it scrolls away with the page and must never snap or pin. FLOATING TWIN (`.mfloat`, a separate element right after `.mbar`): once the capsule is fully out of view plus ~48px more (`.mbar.is-stuck`, set in `placeNav()`), the twin drops in smoothly from above the screen (560ms) to the nav's spot in the nav's skin and height (56px at 16px; phones 43px at 10px; dark glass, 0.5px hairline, edge light via `data-edge`); scrolling back it slides out upward (320ms) just before the original returns. The twin's chips are copies made by `syncFloat()` in products.js that pass clicks to the real chips (no ids/ARIA, never focusable, `aria-hidden`).

# Motion (rule OVERRIDDEN 2026-10-06 — Bugatti-style motion approved by the user)
- The earlier "keep it very subtle" rule (8px/640ms reveals, 60ms stagger, 1px hover lift, "never larger/faster/bouncier") is RETIRED. Site motion now follows `MOTION-REPORT.md` (the bugatti.store audit) in BOTH themes: the six-curve timing system — hovers/state changes 500ms `cubic-bezier(.3,1,.3,1)`; fast 300ms / short 200ms `cubic-bezier(.7,0,.3,1)`; drawers, dropdowns and modals 600ms `cubic-bezier(.7,0,.2,1)` with an 800ms scrim and a 500ms content fade (100ms delay on close); scroll reveals 1000–1500ms `cubic-bezier(.16,1,.3,1)` (fade-up from 2rem, fade-up-large from 90%, zoom-out from 1.3, +30ms per word on split headlines); list/menu items glide 600–1000ms `cubic-bezier(.075,.82,.165,1)` with 100ms stagger; grids 50px/500ms/100ms (phones 30px/300ms/50ms); magnet spring 1.5s (10px, round tools); tabs/accordions 150–250ms ease — and the behaviours in the report's §3 mapping (liquid button fills + 100ms text-colour delay, underline-draw links, close-× rotation, 1.05 image zoom + CTA rise on product cards, footer curtain, clip-path banner reveals, sticky buy bar rise, sheet gestures, dots with rings, hero crossfade at 6s).
- What does NOT change with motion: layout, sizes and colours (banners, cards, controls keep their decided geometry); animate only transform / opacity / clip-path / background-size / box-shadow — never width, height, margins or layout. Day and night get the SAME motion with their own colours (day: ink/navy fills on white; night: white fills, red accent). Every hover, fill, magnet and cursor effect is gated by `(hover: hover) and (pointer: fine)`; `prefers-reduced-motion` sets durations to 0 and skips reveals, parallax and marquees; the edge-light rule still stands (nothing runs backwards or bounces — springs settle, no overshoot beyond the magnet spring).
- Shared plumbing stays in `site/css/motion.css` (linked after controls.css) + `initMotion()` in common.js: content is only hidden when JS adds `.wu-motion`, and the position sweep guarantees nothing stays invisible.
- LANDED 2026-10-06 (phases 1–5, both themes, no layout/size/colour changes): `motion.css` holds the tokens (`--m-primary/--m-fast/--m-short/--m-smooth/--m-drawer/--m-scrim`, `--e-reveal/--e-glide/--e-spring`) and every CSS piece; common.js has the engine — `initMotion()` marks reveals (`[data-rv]` = up / up-large / words / zoom / grid; `splitWords()` wraps heading words, gradient headings get up-large; grids stagger 100ms via `--rv-d`, 50ms on phones; `WU.revealWords(el)` for headings written later), drives the scroll-bound footer curtain (`--sd-p` on `.footer`) and banner clip-reveals (`[data-sd="clip"]` + `.is-clipping` + `--sd-q` on `.promo, .bulk, .duo__card, .cta-band, .quote-band, .pp__card, .feat__slide, .nh-show, .nh-glow, .nh-live`), adds `.wu-fill` (liquid fill via `::before`, `--fill/--fill-text` per button class and theme, pointerenter snaps the circle to +76% then 0, pointerleave sends it to −76%) and `.wu-mag` (icon follows the pointer: `--mx/--my` on the `> svg`, strength `data-magnet` default 10px; `.is-x` close buttons also rotate 90°); `WU.slide(panel, open)` animates every accordion (FAQ, footer groups, menu departments in day, filter sections) with height 250ms + content 150ms; `WU.staggerCards(container)` re-staggers a grid after a tab swap (budget rail, night budget segment); the hero autoplays every 6s and re-reveals its copy per slide; the search overlay fades/drops in and types its own placeholder (`typeHint`); cart, filter, menu drawers and the sort menu use 600/800/500ms and release after 850ms; `.buybar` rises 15px over 1s; `.cartd__ship i` / `.rv__bar i` animate `--pct` / `--w` (registered with `@property`). Nav category pills grow behind the label (`::before` scale .6 → 1) — the burger/search/wishlist/cart tools still have NO hover effect (user rule). Phones: hover/fill/magnet are off (pointer: coarse); every slide-in panel is a bottom sheet in both themes (see PANEL SYSTEM).
- NOT done (deliberately, from the report's optional list): custom cursor, phone dock, hotspots, number counters, floating labels, media parallax (would need a 6–8% image crop). Add them only on request.
